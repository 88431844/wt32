# PVE 节点与虚拟机导航重构设计

## 目标

重构 480 x 320 WT32-SC01 的 PVE 页面，移除页面内 `PVE 总览`、顶部 VM
按钮及详情左右切换按钮。进入 PVE 时首先显示节点信息，通过底部长条按钮进入
虚拟机列表，再从 VM 名称进入单台虚拟机详情。

页面沿用现有石墨青主题、顶部 NAS/PVE/设置导航和数据刷新机制。节点信息按明确
层级分组，避免现有概览、子导航和高密度表格同时出现。PVE 官方节点 API 不提供
CPU 温度，因此本次不创建温度字段、占位符或额外采集服务。

## 页面结构

### 节点信息页

PVE 顶部导航被点击时，页面总是先回到节点信息页。内容区按以下顺序排列：

1. 40 像素身份行：在线状态点、PVE 名称、PVE 版本、节点 IP、节点运行时间。
2. 58 像素指标行：左侧窄列显示 CPU 使用率，右侧宽列显示 1、5、15 分钟系统负载。
3. 58 像素指标行：左侧窄列显示内存已用/总量，右侧宽列显示根存储已用/总量。
4. 40 像素处理器通栏：CPU 核心数与处理器型号。
5. 底部长条 `虚拟机列表` 按钮，并显示运行中数量与总数量。

CPU 与内存使用相同的左侧窄列宽度；系统负载与存储使用相同的右侧宽列宽度，
两行的纵向分割线完全对齐。CPU、内存和存储保留进度条。长处理器型号保持单行，
超出可用宽度时裁切，不增加页面高度。

### 虚拟机列表

点击底部 `虚拟机列表` 按钮进入 VM 列表。列表采用 NAS 页面相同的主体加右侧竖向
分页结构，每页显示四台虚拟机。

每行在同一水平基线上依次显示：

- 状态点及可点击的 `VMID 名称`；
- IPv4 地址；
- CPU 使用率；
- 内存已用/总量。

IP、CPU 和内存必须与 VM 名称同行显示。列表不显示磁盘，磁盘信息保留在 VM
详情页。只有 VM 名称区域进入对应 VM 详情；点击表头、IP、CPU、内存、行间空白
或列表背景返回节点信息页。右侧上、下分页按钮停止事件冒泡，仅执行分页。

### 虚拟机详情

VM 详情继续使用一个可复用内容面，显示现有字段：VMID 与名称、运行状态、IPv4、
CPU 使用率与核心数、内存已用/总量、磁盘已用/总量、运行时间和 Guest Agent 状态。
详情顶部保留紧凑返回图标；点击返回图标或详情主体返回 VM 列表，不创建顶部 VM
子导航或左右切换按钮。

## 数据来源与模型

节点数据继续来自：

`GET /api2/json/nodes/{node}/status`

现有快照已经包含 PVE 名称、配置 Host、版本、CPU 使用率、CPU 核心数、系统负载、
内存和根存储。本次补充解析并保存：

- `uptime`：节点运行秒数；
- `cpuinfo.model`：CPU 型号。

PVE 名称仍来自已配置节点名，节点 IP 仍来自已配置 PVE Host。VM 列表和详情继续
使用 `GET /api2/json/cluster/resources?type=vm` 以及现有 QEMU Guest Agent/LXC
接口获取 IPv4。

不采集或显示 CPU 温度，因为 PVE 标准 REST API、节点状态接口和现有 RRD 数据源
均不提供可靠的各核心温度。

## 状态与事件

- PVE 顶部导航事件将内部视图重置为节点信息页。
- 节点页、VM 列表和 VM 详情使用明确的三态视图状态，不再依赖顶部按钮选中状态。
- 进入 VM 列表时保留当前分页；快照缩短时将分页偏移收敛到最后一个有效页面。
- 选中的 VM 在新快照中消失时返回 VM 列表。
- VM 列表名称按钮、分页按钮和详情返回事件必须停止冒泡，避免同时触发上层返回。
- 首次加载、未配置或离线且没有缓存时，节点页显示现有状态消息，其余值显示 `--`；
  没有有效 VM 数据时列表按钮保持可见，但 VM 列表显示空状态。
- 刷新失败且存在缓存时继续显示上次数据，并沿用现有 2.5 秒刷新失败提示。

## 组件边界

- `components/app_model/include/app_snapshot.h`：只负责新增节点运行时间和 CPU 型号字段。
- `components/app_model/live_provider.c`：只负责从节点状态响应解析新字段。
- `components/dashboard_ui/dashboard_ui.c`：负责三态页面、固定几何、分页与触摸事件。
- `tests/test_dashboard_ui_contract.py`：覆盖布局字段、已移除控件、导航和事件冒泡契约。
- `tests/test_monitor_migration_contract.py`：覆盖节点 API 新字段的模型与解析契约。

不改变 PVE TLS、Token 鉴权、配置页面、刷新间隔、NAS 页面或后端网关契约。

## 验证

- 契约测试确认 `PVE 总览`、顶部 VM 按钮、详情左右按钮及相关状态已移除。
- 契约测试确认节点身份行四组信息同排、两个指标行使用相同列宽、处理器为较矮通栏。
- 契约测试确认节点运行时间与 CPU 型号来自节点状态 API，CPU 温度不存在。
- 契约测试确认 VM 每页四行，并在同一行显示名称、IP、CPU 和内存。
- 契约测试确认 VM 名称进入详情，其他列表区域返回节点，分页按钮不触发返回。
- 契约测试确认详情主体返回 VM 列表，VM 消失与分页缩短时状态正确收敛。
- 运行完整 Python 测试、原生测试和 ESP-IDF 4.4.8 固件构建及大小检查。
- 使用浏览器以 480 x 320 检查节点、VM 列表、VM 详情、离线和空状态，确认没有裁切、
  重叠或意外换行。
- 在已连接 WT32-SC01 上无擦除烧录，检查串口启动与 PVE 刷新日志，并在实机验证触摸热区。

## 范围外

- CPU 各核心温度、`node_exporter` 或自定义 PVE 采集服务。
- VM 启停、重启或控制台等写操作。
- PVE 数据采集网关化或多节点切换。
- NAS 页面、设置页和全局顶部导航的视觉重构。
