# 动态监控数据与图标界面设计

## 目标

WT32-SC01 的 PVE 虚拟机、NAS 存储池和 NAS 物理硬盘必须完整展示接口实际返回的数据，不再使用业务数量上限或静默截断。页面继续按屏幕容量分页，但总页数由当前完整快照动态计算。

NAS 页面同时采用已确认的图标和底部状态布局：顶部 NAS 与 PVE 入口使用品牌标志，存储池、硬盘和运行指标使用适合小屏的硬件图标，底部将静态信息放左侧，将四项动态指标等宽平铺在右侧。

本设计覆盖旧设计中与固定集合上限、NAS 底栏尺寸和底栏两行三列排布冲突的部分。既有 NAS 存储池/硬盘列表切换语义保持不变。

## 方案选择

采用“堆上不可变完整快照 + 所有权转移”的数据模型：采集任务在后台构建完整候选快照，只有全部采集和分配成功后才交给 UI；UI 始终保留上一份完整快照，直到收到新的完整快照。

未采用以下方案：

- 扩大 `APP_MAX_*` 常量。该方案仍会在设备数量继续增加时截断数据，只是推迟问题。
- 分批把不完整数据直接推给 UI。该方案会在刷新期间显示半份列表，失败时还会覆盖上一份完整缓存。
- 固定超大数组。该方案持续占用有限 RAM，且仍然存在人为上限。

## 动态数据模型

### 集合表示

- 删除 PVE 虚拟机、NAS 存储池、NAS 物理盘的固定长度数组和 `APP_MAX_PVE_GUESTS`、`APP_MAX_NAS_POOLS`、`APP_MAX_NAS_DISKS` 业务上限。
- 三个集合改为动态连续数组，以指针和 `size_t count` 表示实际元素数量。
- 快照提供明确的创建、扩容、克隆、移动和释放辅助函数。所有失败路径必须释放候选快照已取得的内存。
- 每份发布后的快照不可变。UI 不修改数组内容，只更新视图偏移和选中状态。

### 队列所有权

- FreeRTOS 队列传递快照指针，不再按值复制包含数组的结构体。
- 采集任务拥有候选快照；成功送入队列后，所有权转移给队列/UI。
- 队列只保留最新完整快照。替换尚未消费的旧快照时，先取出并释放旧指针，不能因覆盖指针而泄漏。
- UI 收到新快照后原子替换当前快照，并释放之前持有的快照。页面渲染期间快照保持有效。

## 数据采集

### PVE

- HTTP 响应体按接收数据几何扩容，不再使用 `HTTP_RESPONSE_MAX` 作为静默截断边界。
- JSON 解析成功后按实际数组长度一次性分配虚拟机数组，并逐项填充。
- HTTP 未完整结束、JSON 不完整、元素转换失败或任何内存分配失败时，整次候选刷新失败；不得发布部分虚拟机列表。

### NAS SNMP

- 存储池和物理硬盘按 OID 子树持续遍历，直到收到明确的子树结束条件。
- 动态数组按需扩容，不再以循环次数或 `APP_MAX_*` 停止采集。
- 每个返回 OID 必须严格大于前一个 OID；代理返回重复或倒退 OID 时立即判定本次遍历失败，避免异常代理导致无限循环。
- 单次 SNMP 交换继续使用网络超时保护，但完整集合不得因固定数量或固定总采集预算而提前结束。
- 交换超时、OID 解析异常、子树未正常结束或分配失败时，整次 NAS 候选刷新失败；不得用半份存储池或硬盘列表覆盖缓存。

## 加载、缓存与失败状态

- 缓存指当前启动周期内最近一次完整成功快照，不写入 NVS。
- 第一次请求尚未结束且没有缓存时，页面显示 `数据加载中`。
- 第一次完整请求超过其请求超时仍未成功且没有缓存时，页面才显示设备离线。
- 后续刷新失败时继续正常显示上一份完整缓存，不显示持久错误横幅或离线缓存文案。
- 后续失败在 NAS/PVE 内容区中央显示 Toast：`刷新失败，已显示上次数据`。
- Toast 持续约 2.5 秒，淡入、短暂停留、淡出；对象不可点击，不拦截列表和翻页触摸。
- 连续失败可以再次触发 Toast，但同一次失败事件只显示一次。

## 分页与交互

### PVE 虚拟机

- 每页可见数量继续由现有页面几何决定。
- 总页数和末页偏移只根据当前 `guest_count` 计算，不再钳制到固定上限。
- 新快照数量减少导致当前偏移越界时，偏移收敛到新的最后一页。

### NAS 存储池

- 默认显示存储池列表，每页四项。
- 超过四项时在列表右侧显示竖向上翻、页码、下翻控件；页数由实际 `nas_pool_count` 计算。
- 存储池行给右侧翻页列预留空间，容量、类型和进度条不得被按钮覆盖。
- 点击存储池列表中除上下翻页按钮外的区域，切换到整台 NAS 的物理硬盘列表。

### NAS 物理硬盘

- 每页四项，总页数由实际 `nas_disk_count` 计算。
- 列表继续只显示状态、HDD 图标、硬盘编号、型号和温度，不恢复容量列。
- 右侧使用竖向上翻、页码、下翻控件。
- 点击物理硬盘列表中除上下翻页按钮外的区域，返回存储池列表。

## 图标系统

### 品牌入口

- NAS 顶部按钮使用 Synology DSM 蓝底白字标志，并保留 `NAS` 文字。
- PVE 顶部按钮使用 Proxmox 橙白/橙灰 X 标志，并保留 `PVE` 文字。
- 品牌标志从 Proxmox、Synology 官方视觉资产制作，不能直接采用 Iconfont 中来源不明的用户上传副本。
- 品牌图像离线编译进固件，不运行时联网加载。

### 硬件与状态图标

- CPU 使用参考 Proxmox 硬件页的方形带引脚 Processor 图标。
- 内存使用 DIMM/Memory 图标；硬盘使用实体 HDD/盘仓轮廓；存储池使用数据库/存储堆叠图标。
- 温度、IP、运行时间、上下行网络和翻页按钮使用同一线宽的单色图标。
- 单色图标制作成 16 px 左右的离线 LVGL 图标资源，随主题颜色重着色；品牌图标保留官方颜色。
- 小尺寸下以辨识度为准，删除无法在 16 px 清楚呈现的内部细节。

## NAS 底部状态栏

### 几何

- NAS 底栏宽 464 px、高 42 px，位于页面底部；存储池内容区相应缩短，四个列表行和右侧翻页列仍完整可见。
- 底栏内边距 8 px，使用固定列宽和等宽数字，接口值变化时布局不左右跳动。
- 左侧静态区依次显示 IP 图标与完整 IPv4 地址、时钟图标与紧凑运行时间，不显示 `IP`、`运行` 文字标签。
- 右侧 CPU、内存、温度、网络四项各占 68 px，水平等宽平铺，并用细分隔线建立节奏。
- CPU、内存、温度只显示图标和数值；网络单元内部上行在第一行、下行在第二行。

### 数值格式

- IPv4 地址必须完整显示。最长 IPv4 使用紧凑等宽数字字号，不使用省略号。
- 运行时间以天显示；超过 999 天后自动换算为年，避免静态区无限增长。
- CPU、内存完整支持 `0%` 至 `100%`。
- 温度完整支持三位数和不可用值 `--`。
- 网络速率根据实际值自动选用 `B/K/M/G/T` 单位，最多保留一位小数；上、下行各自完整显示，不裁切。
- 数值不可用时保留单元和图标，数值显示 `--`，不改变布局宽度。

## 内存与降级策略

- 动态集合只受当前可用堆内存约束，不设置业务数量上限。
- 内存不足时本次候选刷新失败，保留上一份完整快照并按已有/无缓存规则展示 Toast 或离线状态。
- 没有缓存的首次分配失败按首次请求失败处理，先保持加载状态，达到请求超时后显示离线。
- 采集和 UI 日志记录实际元素数量、分配失败和被丢弃的候选刷新，便于设备诊断。

## 验证

- 模型测试覆盖超过旧上限的数据，例如 25 个 PVE 虚拟机、12 个存储池和 10 块物理硬盘，确认全部元素可访问且分页末页正确。
- 测试 PVE 动态响应体扩容、SNMP 子树完整结束、候选快照所有权转移和全部释放路径。
- 注入中途请求失败和内存分配失败，确认上一份完整缓存不被部分候选覆盖。
- 测试首次加载、首次超时离线、后续失败 Toast、Toast 自动淡出和不拦截触摸。
- UI 契约测试覆盖存储池/硬盘双向切换、两个列表的动态分页和按钮事件隔离。
- 底栏使用最长 IPv4、`999天`、`100%`、三位温度、`999.9G`/`102.4M` 网络速率进行布局压力测试，确认无截断、重叠和位置跳动。
- 在浏览器原型中核对普通值与压力值布局，并对品牌图标和 Processor/HDD 图标做截图检查。
- 运行完整契约测试和 ESP-IDF 构建；非擦除方式烧录设备，通过串口日志确认启动、PVE/NAS 刷新数量和无异常重启。
- 实机触摸验证存储池与硬盘列表切换、上下分页、Toast 触摸穿透和所有主题下的图标可读性。

## 范围外

- 不推断 NAS 物理硬盘与存储池的成员关系。
- 不把监控快照持久化到 NVS 或文件系统。
- 不改变 PVE、NAS 或 SNMP 接口认证方式。
- 不改变每页可见行数；本次移除的是总集合上限，不是屏幕分页。
