# NAS 指标与底栏修复设计

## 目标

修正 WT32-SC01 NAS 页面中与 DSM 不一致的运行时间和内存占用，并让底部两行指标采用稳定、左对齐的固定位置布局，避免网络速率变化造成文字左右跳动。

## 数据来源与计算

- NAS 指标继续由 ESP32 通过 SNMP 直接采集，不经过 gateway API。
- 系统运行时间优先读取 HOST-RESOURCES-MIB `hrSystemUptime.0` (`1.3.6.1.2.1.25.1.1.0`)。该值与 DSM 的系统运行时间语义一致。
- 若 NAS 不支持 `hrSystemUptime.0`，回退到 SNMPv2-MIB `sysUpTime.0` (`1.3.6.1.2.1.1.3.0`)，确保旧设备仍能显示可用值。
- 内存继续读取 UCD-SNMP `memTotalReal.0` 和 `memAvailReal.0`，并增加 `memBuffer.0` 与 `memCached.0`。
- 当四项数据均有效且 `available + buffer + cache <= total` 时，按 `(total - available - buffer - cache) / total * 100` 计算占用率，使口径接近 DSM 资源监控。
- 若 buffer 或 cache OID 不可用，则回退到现有的 `(total - available) / total * 100`，保持兼容性；所有运算先校验范围，避免无符号下溢。

## 底栏布局

- 保持现有 36 像素双行底栏和两行三列的信息结构。
- 第一行依次显示 CPU、内存、温度；第二行依次显示网络、NAS IP、运行时间。
- 六个单元格均使用固定坐标、固定宽度和左对齐，动态文本不再居中。
- 网络单元拆成三个独立标签：固定的 `网`、固定起点的上传 `↑...`、固定起点的下载 `↓...`。任何一个速率位数变化都不会移动另外两个标签。
- 动态值仍使用现有 `B/s`、`K/s`、`M/s`、`G/s` 紧凑格式；不可用时显示 `--`。

## 状态与兼容

- NAS 离线或缓存快照时继续隐藏旧指标，显示 `--`。
- 运行时间两种 OID 均不可用时显示 `运行 --`。
- 内存基础 OID 无效或数值越界时显示 `内存 --`。
- 不改变 NAS 在线判定、网络采样逻辑、刷新间隔、主题和字体。

## 验证

- 契约测试确认系统运行时间 OID 的优先级与回退路径。
- 契约测试确认内存计算包含 buffer/cache、兼容回退以及下溢保护。
- UI 契约测试确认两行标签左对齐，网络标签拆分并使用固定坐标。
- 运行完整 Python 契约测试和 ESP-IDF 固件构建。
- 刷写后通过串口日志确认 NAS 刷新成功；最终数值与 DSM 页面进行实机对照，网络速率变化时观察底栏位置不移动。

## 范围外

- 不接入需要 DSM 账号的 WebAPI。
- 不修改网速接口选择和速率计算。
- 不调整 NAS 页面其他布局或交互。
